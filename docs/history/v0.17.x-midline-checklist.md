# `v0.17.x` Midline Checklist

This page is the execution checklist for the second half of the active
`v0.17.x` line.

Use it when the question is:

- what should still close before `v0.17.x` hands off to `v0.18.x`?
- which work belongs to this line instead of drifting into random feature
  growth?
- what evidence should survive the line instead of living only in terminal
  memory?

For the line snapshot, see
[docs/history/v0.17.x.md](docs/history/v0.17.x.md).

## Midline Posture

`v0.17.x` is now past the early-open phase.

The line already has:

- family-first protocol growth discipline
- stronger compiler/IR field-contract posture
- dataflow topology documentation
- debugger-console publication surfaces
- `etragon` federation learning shape
- clearer `gewyvern` / `etragon` / `leserpent` role boundaries

The remaining task is not to keep adding unrelated breadth.
The remaining task is to make the line feel coherent enough that `v0.18.x` can
focus on runtime confidence and validation instead of cleaning up `0.17.x`
spillover.

## Exit Themes

### 1. Protocol-Cluster Coherence

- [ ] choose one or two priority protocol clusters as the `v0.17.x` proof set
- [x] expand one local discovery proof cluster with sibling entries instead of
      one-off protocol additions
- [ ] ensure each chosen cluster has healthy-path and failure-path entries
- [ ] ensure registry, alias, shelf, docs, and tests agree for those clusters
- [ ] ensure operator guidance reads like module diagnosis, not protocol
      identity only
- [ ] archive at least one compact protocol-surface evidence snippet

### 2. Gewylang And IR Maturity

- [ ] make package/module composition rules easy to cite from docs
- [ ] ensure comment support, modular structure, and lightweight inference
      behavior are covered by tests or reference docs
- [ ] keep lowering explanations structured enough for line-to-line comparison
- [ ] ensure `gewyc` JSON wrapper contracts name preferred grouped payloads
- [ ] archive one representative IR snapshot for a protocol-package path

### 3. Debugger And Publication Surfaces

- [ ] ensure local debugger console and API debugger console rank targets
      consistently
- [ ] name debugger-console JSON as contract-candidate or evolving surface
- [ ] ensure publication surfaces do not infer truth outside runtime/export data
- [ ] ensure new fields point to stable owners in docs

### 4. Etragon Federation Boundary

- [ ] keep federation as learning aggregation, not fleet orchestration
- [ ] keep runtime identity in all federated target outputs
- [ ] expose federation status without overwriting `gewyvern` diagnosis truth
- [ ] add a stack or CLI smoke that proves unavailable runtimes degrade
      structurally instead of crashing
- [ ] decide whether daemon federation should poll many target indexes directly
      in `v0.17.x` or wait for `v0.18.x`

### 5. Multi-Instance Evidence

- [ ] run at least one two-runtime `gewyvern` scenario with `leserpent`
      registered against both
- [ ] run one `etragon` sidecar or federation path against the same posture
- [ ] preserve any produced resilience or federation summary artifact in the
      line notes when it matters
- [ ] confirm degraded-runtime behavior is visible rather than silent

### 6. Documentation Coherence

- [ ] update roadmap/current-line wording to stop calling `v0.15.x` current
- [ ] link the dataflow topology from active architecture and stack pages
- [ ] ensure `v0.17.x` docs point to the current checklist
- [ ] keep book/reference/how-to pages aligned on sidecar versus federation
      wording

## What Should Not Enter Late `v0.17.x`

Avoid late-line work that:

- adds large new protocol families without tests and docs
- widens machine surfaces without contract notes
- turns `etragon` into a control plane
- turns `leserpent` into a runtime truth source
- adds remote attach semantics to `gewyvern` core
- makes `gewylang` cleverer without making IR review clearer

If the work is useful but does not help close this checklist, it probably
belongs to `v0.18.x` or later.

## Handoff Bar To `v0.18.x`

`v0.17.x` should hand off when:

- one protocol-cluster proof set is coherent
- `gewylang` and IR surfaces feel reviewable rather than magical
- dataflow and stack topology docs match current code direction
- debugger publication surfaces have an explicit contract posture
- `etragon` federation is clearly bounded as learning aggregation
- the next line can start from validation and runtime confidence, not cleanup

That is the right moment to let `v0.18.x` become the broader protocol/runtime
confidence line.
