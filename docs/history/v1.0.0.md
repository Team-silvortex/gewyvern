# v1.0.0 Stable Snapshot

This page records the meaning of the active `v1.0.0` line.

`v1.0.0` starts after the `v0.20.x` sealing line proved that the packaged
release gate, the multi-project stack smoke, the pathological ingest gate, the
remote Linux host validation path, and the practical Linux target-lab shelves
could all be treated as one deliberate release posture instead of as scattered
green commands.

The purpose of this line is to name that sealed posture clearly and keep it
stable.

## What v1.0.0 Means

The line means:

- the runtime, CLI, machine-readable validation outputs, and documentation
  shelves now have an intentionally stable core
- release judgment should begin from repeatable native validation entrypoints,
  not from remembered shell sequences
- Linux-host execution, attach proof, and conservative target-lab evidence are
  now part of ordinary release confidence for the core system
- `gewylang`, `gewyc`, `etragon`, and `leserpent` should keep following one
  shared mainline version without reopening release-line drift
- future widening should happen as deliberate post-`1.0.0` work, not as hidden
  instability inside the first stable line

## What This Line Inherits

By the time `v1.0.0` opened, the project already had:

- a packaged protocol catalog with family hubs, shelves, alias docs, and
  registry validation
- a green packaged `deb+rpm` release validation path
- a green multi-project Docker smoke across `leserpent`, `etragon`, and many
  `gewyvern` runtimes
- a green pathological ingest gate that preserves degraded-but-live runtime
  behavior under malformed clients
- a green debugger cross-validation path across runtime, console, and compiler
  surfaces
- a green remote Linux host validation path with package, runtime, and eBPF
  evidence
- practical Linux target-lab shelves for suspicious HTTP behavior, rejected FTP
  authentication, and rejected LDAP bind evidence

## Current Catalog Anchor

At this `1.0.0` checkpoint, the repository-level protocol shelf scans as:

- 70 protocol family directories under `protocols/`
- 363 packaged protocol entries under those family directories

Treat those numbers as the current catalog anchor for stable-line docs and
validation notes. Older history pages may preserve smaller counts because they
describe earlier lines.

## What This Line Adds

The active work is no longer "discover whether the core can hold together."

The active work is:

- preserve the sealed release gate as the first stable answer
- keep machine contracts, artifact indexes, and failure surfaces synchronized
- keep the Linux proof path and practical target-lab shelves easy to rerun
- make documentation read like one stable system instead of one near-finished
  convergence story
- treat later widening as explicit change management rather than as casual
  growth
