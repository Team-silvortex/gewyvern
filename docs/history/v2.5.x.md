# v2.5.x Maintenance Line

This line continues the released Gewyvern, Leserpent, and Leselang system.
The [2.0.0 release baseline](v2.0.0-release-notes.md), MIT open-source free core,
and existing wire/authority contracts remain unchanged. Product versions do
not renumber language contracts, journal schemas, or retained evidence.

## 2.5.0: Shared Release Alignment And Adapter Separation

- Align the Rust workspace, .NET version, local lockfiles, status checkpoint,
  and active documentation on `2.5.0`. Desktop and mobile product versions
  continue to inherit this shared version.
- Carry forward the [2.4.x independence work](v2.4.x.md): product policy for
  group graph registration, dispatch claims, finalization, successor admission,
  and progress projection now lives in the command adapter. Native owners
  retain storage, evaluator authority and transaction lifetime. Progress reads
  keep one snapshot rather than combining observations from different commits.
- Record the current contracts without promoting incomplete work: reference
  execution `1.170.0`, native embedding `0.172.0`, HIR `0.184.0`, and journal
  schema `10`. Native embedding remains Developing/Draft at completion 10;
  `complete_vm` and `full_extraction_gate` remain false.
- Continue acceptance-gated extraction: complete two-host verticals, native VM
  product-DTO separation, host-neutral durable graph recovery, and full reference
  wire/authority/GUI/CLI/journal parity still decide repository readiness.
  There is no version-triggered move or replacement extraction deadline.
- Keep release alignment separate from evidence generation. The version tool
  no longer relabels retained macOS preflight reports with new versions while
  keeping old binary hashes. Tests use temporary synthetic current-version
  inputs, and real release validation still rejects stale reports.
