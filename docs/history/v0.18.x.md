# v0.18.x Minor Snapshot

This page records the meaning of the active `v0.18.x` line.

`v0.18.x` is the point where `gewyvern` should stop feeling like a collection
of promising protocol pieces and start feeling like a packaged network
debugger that can be exercised on real Linux hosts.

## What v0.18.x Means

The line means:

- protocol families should keep expanding, but with standard-library style
  organization and validation
- runtime behavior should be tested through installed packages, not only
  through source-tree cargo tests
- multi-instance and degraded-runtime paths should stay boring and repeatable
- Gewylang and IR surfaces should remain reviewable as protocol coverage grows
- packaging metadata should match the current minor line instead of carrying
  stale development-era version numbers

## What Is Whole Enough Now

By the time `v0.18.x` opened, the project already had:

- broad protocol-family coverage across transport, auth, database, messaging,
  management, tunnel, and cache surfaces
- registry validation that can sweep every packaged protocol entry
- standalone runtime validation for socket ingest and latest-snapshot APIs
- a three-module smoke path for `gewyvern`, `leserpent`, and `etragon`
- native package layout metadata through `package-compat.toml`

## What This Line Adds

The active work is to make the breadth operational:

- keep native packages self-describing through `package_version` and
  `release_line`
- prove DEB/RPM package installs in clean containers
- keep protocol manifests aligned with the current source release
- make Docker and physical-host validation less dependent on one public mirror
- record failures as release blockers when they indicate stale contracts rather
  than transient infrastructure noise

is that the whole project can now be built, packaged, installed, and exercised
as one debugger-shaped system.

### Runtime Lifecycle Control Pass

The `2026-06-28` lifecycle pass added
`scripts/validation/runtime_lifecycle_validation.sh` to make start/stop behavior
explicit instead of inferred from broad cargo tests.

The script validates:

- bounded startup exits after its session budget
- malformed socket input is logged, backed off, and followed by a recovery event
- a long-running API/socket process can be stopped explicitly
- PID, API reachability, socket reachability, and temporary run directories are
  cleared after stop
- retained evidence stays under `target/validation/runtime-lifecycle`

This pass exposed two runtime-control issues. The API service now has an owned
shutdown handle that signals and joins the accept loop, and the serve loop now
counts handled sessions explicitly so idle timeouts do not consume the operator
session budget. Sampling also showed persistence repeatedly rescanned the
protocol registry while writing catalog artifacts, so persisted protocol
surfaces now reuse one cached protocol-summary set per snapshot write.

Validation that passed locally after the fix:

- `scripts/validation/runtime_lifecycle_validation.sh`
- `cargo test -p gewyvern api_persistence -- --nocapture`
- `cargo test -p gewyvern reports -- --nocapture`

- `cargo test -p gewyvern protocol_profiles -- --nocapture`

The `api_persistence` shelf dropped from the previously observed slow
multi-minute-feeling path to about 3s locally after removing the repeated
registry scans.

The Ubuntu physical-host rerun then exposed two test-environment portability

### Native Debugger Cross And Negative Validation

The next reliability pass added the first Rust-native validation harness:
`cargo run --quiet --bin gewyvern_validate -- debugger-cross`. This starts the
migration away from shell-owned test logic while keeping
`scripts/validation/debugger_cross_validation.sh` as a compatibility wrapper.

The harness cross-checks the same scenarios through multiple surfaces:

- runtime summary JSON
- local debugger-console JSON
- `gewyc envelope` JSON

It also includes negative checks:

- `http_connect_denied_path.gewy`
  must remain `attention` with `missing_transition` and
  `collect_more_runtime_evidence`.
- `socks5 --entry auth-connect-denied`
  must remain `attention` with `missing_transition` and
  `collect_more_runtime_evidence`.
- an invalid Gewylang file must fail at parse before validation or diagnostics
  can claim success.

The same native harness line now also owns registry package validation through
`cargo run --quiet --bin gewyvern_validate -- registry`. It scans

`cargo run --quiet --bin gewyvern_validate -- high-frequency`. That command

overconfident debugger output. The legacy
`scripts/validation/high_frequency_validation.sh` entrypoint remains as a thin
compatibility wrapper.

The first process-owning native validator is now
`cargo run --quiet --bin gewyvern_validate -- runtime-lifecycle`. It builds the
local runtime binaries, starts bounded and long-running `gewyvern --serve`
instances, verifies health/readiness, injects malformed socket input, confirms
recovery evidence in runtime logs, stops the service, and checks API/socket
unreachability after shutdown. The legacy
`scripts/validation/runtime_lifecycle_validation.sh` entrypoint remains as a
thin compatibility wrapper.
