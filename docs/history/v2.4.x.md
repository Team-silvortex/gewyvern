# v2.4.x Maintenance Line

This line continues the released Gewyvern, Leserpent, and Leselang system.
The [2.0.0 release baseline](v2.0.0-release-notes.md) and existing open-source
core guarantees remain unchanged. Shared product versions do not renumber
frozen protocols, schemas, or historical validation evidence.

## 2.4.0: Shared Release Alignment And Continued Leselang Independence

- Align the Rust workspace, .NET product version, local package lockfiles,
  release metadata, status checkpoint, and active documentation on `2.4.0`.
  Desktop bundles, mobile display versions, and Rust services continue to
  inherit the shared version rather than introducing component release numbers.
- Continue the acceptance-gated Leselang independence work carried by the
  [2.3.x line](v2.3.x.md). Shared-owner restoration now composes pending parent
  sessions and prepared Seq/All collectors under the original local scope.
  Native embedding remains `0.168.0`, Developing/Draft at completion 10;
  reference execution remains `1.105.0`.
- Verify native source checkpoints with a fresh disposable build target rather
  than reusing monorepo build artifacts. Verification cleans its owned cache
  before publishing the source export; failure does not publish a successful
  checkpoint. The exported native facade is still not the complete reference VM.
- Retain the remaining gates: complete two-host source/effect/reply/capture/cancel
  verticals, native VM product-DTO separation, host-neutral durable graph
  recovery, and reference wire/auth/GUI/CLI/journal parity. Physical repository
  extraction has no replacement version or date; `complete_vm` and
  `full_extraction_gate` remain false.
