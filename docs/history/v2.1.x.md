# v2.1.x Maintenance Line

This line maintains the released Gewyvern, Leserpent, and Leselang system.
The [2.0.0 release baseline](v2.0.0-release-notes.md) and existing open-source
core guarantees remain unchanged. Product versions do not renumber frozen
protocol, schema, or historical evidence versions.

## 2.1.6: Host-Neutral Runtime Foundation And Bounded Flow Composition

- Add bounded ordered `string_list` construction, splitting, indexing,
  append/join and type-preserving pure `fold`. Preserve collection, text,
  fuel and expansion limits without suspension inside pure iteration.
- Extend reusable functions with bounded effectful flow composition, hygienic
  result binds, prepared atomic group members and selected named groups/data
  returns. Cold paths remain type/capability checked; only selected preparation
  executes, and committed choices are not recalculated after restart.
- Preserve continuation schemas 1-11, journal schema 10 and closed projection
  vocabularies v1-v5. Original authority, fuel, deadline, raw-output bounds,
  group barriers and transactional first-commit replay remain enforced.
- Introduce `leselang-runtime-core`, a product-free Rust foundation for opaque
  host admission, fuel accounting, portable clock addition and capped retry
  arithmetic. The reference VM uses the same primitives rather than a second
  admission scheduler. Register it in the MIT/free core policy and add a
  dedicated normalized-package CI gate.
- Bound pre-admission attempts and submission-pinned deadlines; preserve
  worker-handoff budgets, local cancellation, explicit host backpressure and
  sibling isolation. Admission has no hidden timer, queue or global lock.
- Add payload-free terminal observation without changing legacy status/poll
  JSON. Acceptance is distinct from output delivery/execution completion;
  callback uncertainty is not rejection or automatic replay authority. Fix
  undelivered-output cleanup when host input destruction unwinds.
- Harden dispatch clock preflight, durable identity-watermark recovery,
  scheduler capacity/fairness and exact retry delays without implicit fuel
  refill or authority changes. Extend native correlated-acknowledgement proofs
  for the new function and collection flows.
- Update embedding/control-flow documentation, status evidence, shared product
  metadata and lockfiles to `2.1.6`. Full evaluator independence, generic host
  operation schemas, effectful loops and host-effect recovery remain unfinished;
  this release does not split Leselang into another repository.

This is a source release. Local language and service regression tests, strict
workspace Clippy, metadata/documentation/fuzz/independence/status checks, and
standalone core package tests cover the implementation boundaries. They do not
claim fresh remote-Linux or live desktop-control proof, signed desktop artifacts,
or a completed current-artifact CI packaging gate. See the
[embedding contract](../leselang-embedding.md) and
[control-flow contract](../leselang-control-flow.md) for exact host obligations
and the remaining extraction gates.

## 2.1.5: Reusable Leselang Functions And Group-Driven Automation

- Add typed reusable pure functions with named scalar parameters, hygienic
  bounded expansion, declaration-order argument evaluation and cold-definition
  checking. Reject recursion, caller-local capture and effectful helper bodies.
- Extend named sequential and flat parallel group results into transactional
  atomic tails, multiple captured successors and typed conditional scalar exits.
  Reserve the longest cold path without early dispatch, preserve the all-success
  barrier, and recover complete journal-owned group/frame context after restart.
- Introduce continuation schemas 7 through 11 while preserving older supported
  forms and journal schema 10. Fence cumulative raw output before projection,
  bounded frame growth, replayable group-budget faults and transaction rollback.
- Add closed GUI projection vocabularies v2-v5 for selection/requirement
  booleans, acknowledged text/form values, canonical kind tokens and four
  optional metadata fields. Older vocabularies retain exact fields without
  synthesis; saved projections must match committed raw receipts and receiving
  host arguments still pass their original validators.
- Add distinct optional strings, explicit construction and presence tests,
  lazy typed defaults, exact text predicates and optional Unicode scalar
  character access. Preserve absent versus empty text, eager text operands,
  shared scan/copy fuel, bounded inputs, authority and cancellation.
- Exercise the Rust native debugger's correlated acknowledgement path for
  helper-driven, group-driven, boolean/text/kind/nullable and text-selected form
  flows without exposing private lexical or projection frames.
- Reduce development cache growth: disable Rust test incremental state,
  select host-specific Avalonia runtime assets for non-AOT development builds,
  reuse validated locked restore graphs only when inputs and expanded packages
  are current, and record NuGet package access times. Portable and release/AOT
  restore graphs remain separate from the opt-in host development build.
- Advance the evolving control-flow contract to `0.23.0` and synchronize the
  shared product metadata and lockfiles on `2.1.5`. Status remains `developing`;
  generic containers/collection iteration, effectful functions/loops,
  host-effect recovery and host-neutral runtime extraction remain unfinished.

This is a source release. After the version update, the local macOS Rust
workspace passed **3,740 tests**, with **35 existing ignored tests**, using all
features and the locked dependency graph. Strict workspace Clippy, metadata,
documentation, fuzz, independence and status checks also passed. The locked
Avalonia development build completed with zero warnings and errors; its next
warm build correctly reused restore metadata. These checks are not fresh
remote-Linux or live desktop-control proof, signed packages, or a completed
current-artifact CI packaging gate.
See the [control-flow contract](../leselang-control-flow.md) and
[development workflow](../development.md) for the implemented boundaries.

## 2.1.4: Durable Leselang Dataflow And Named Group Results

- Add bounded pure scalar `loop`, explicit integer/boolean text conversions,
  and lazy same-type `recover` for local arithmetic and parsing failures.
  Resource, authority, cancellation and host failures remain outside recovery;
  every calculation consumes the original shared fuel.
- Extend atomic result bindings into bounded multi-step chains with typed
  projection frames and conditional scalar exits. Successor admission and
  completion remain transactional, preserve the original authority and budgets,
  and replay the first committed choice across restarts or competing workers.
- Bind named `seq`, `repeat` and flat `all` results through statically checked
  `member` and `field` projections. Only a pure scalar body may follow a captured
  group in this release; parallel groups retain parallel execution.
- Introduce continuation schemas 3 through 6 and migrate older supported
  journals to schema 10. Bound groups require complete original journal recovery;
  isolated member restoration cannot discard their residual calculation.
- Harden raw-output limits before projection, grouped completion rollback,
  corrupted-frame rejection, and whole-group retention, including single-step
  sequences and restart after cumulative output exhaustion.
- Exercise the native debugger's correlated presentation acknowledgement path
  for loops, result chains, conditional exits, conversions, recovery and group
  results without exposing private lexical frames in public projections.
- Fix the pathological-container packaging gate to recognize the current
  `InvalidJson` error class rather than obsolete parser wording. Require the
  rejection class on the same socket-failure record and reject unrelated log
  messages; the runtime's input limits and packaging stages remain unchanged.
- Advance the evolving control-flow contract to `0.12.0`, update its status
  tensor evidence, and synchronize shared product metadata and lockfiles on
  `2.1.4`. Host-neutral extraction, group-driven host effects, effectful loops,
  reusable functions and host-effect recovery remain unfinished.

This is a source release, not a declaration of a completed current-artifact
packaging gate. Local Rust and host-protocol validation does not substitute for
fresh remote-Linux, live desktop interaction, final signed artifacts or the
CI packaging result. See the [control-flow contract](../leselang-control-flow.md)
for exact language and recovery boundaries.

## 2.1.3: Bounded Leselang Computation And Control Flow

- Add durable named `seq` steps and bounded `repeat`, with shared execution
  budgets, ordered dispatch, cancellation, and restart-safe progress. Expanded
  groups remain limited to 64 atomic effects.
- Add typed scalar calculation, immutable lexical `bind`, lazy `choose`,
  checked arithmetic, comparisons, short-circuit logic, and bounded string
  operations. Expanded computation is limited to 1024 nodes and source calls
  retain the 16-level depth fence.
- Accept computed arguments for all 70 current atomic host operations,
  including members of bounded groups. Prepare and validate the entire
  selected group before allocating effect identities or journaling any work.
- Capture one atomic host result and project explicitly typed scalar fields
  into a pure calculation. Save bounded locals and the pure body in
  continuation schema 2; preserve schema 1 atomic/group images and journal
  schema 7. Replay returns the first committed outcome without another effect.
- Extend the native debugger's single-presentation acknowledgement path and
  add recovery, authority, fuel, invalid-image, and source/continuation fuzz
  coverage. Public debugger projections do not expose saved locals or bodies.
- Document the host-adapted embedding direction and evolving `0.5.0`
  control-flow contract. The status tensor keeps this work `developing`:
  result-driven second host calls, general durable control frames, and a
  host-neutral standalone runtime are not implemented by this release.
- Synchronize Cargo, .NET, lockfiles, status metadata, and active documentation
  on `2.1.3`, without relabeling historical release evidence or protocol versions.

This source release does not claim Bash parity, a new desktop scalar inspector,
fresh remote-Linux or live-GUI validation, signed desktop artifacts, or a
completed current-artifact packaging gate. See the
[control-flow contract](../leselang-control-flow.md) for the implemented bounds
and [embedding architecture](../leselang-embedding.md) for the extraction boundary.

## 2.1.2: Workspace And Test Hygiene

- Consolidate 52 protocol-registry integration targets into the shared
  `protocol_registry_tdd` target. All 407 registry tests remain; the root
  package now builds 43 integration targets instead of 95.
- Remove the unused container-validation shell implementation. The native
  Rust runner continues to own timeout and container-cleanup behavior, with
  those checks retained in the native validation contract tests.
- Remove tracked Python bytecode and ignore Python caches and managed test
  outputs so generated files do not re-enter the repository.
- Pin the English help-output test to the `C` locale, independent of the
  developer or Linux server's configured language. Runtime localization is
  unchanged.
- Synchronize Cargo, .NET, lockfiles, status metadata, and current documentation
  on the shared `2.1.2` product version. Earlier `2.1.0` and `2.1.1` commit
  labels had not advanced the build metadata from `2.0.0`.
- Document bounded cleanup of rebuildable outputs while preserving source,
  runtime data, compatibility tests, release evidence, and Git history.
- Require `rustls >=0.23.45` within the compatible `0.23` line and update the
  lockfile to fix [RUSTSEC-2026-0285](https://rustsec.org/advisories/RUSTSEC-2026-0285).
  Keep dependency auditing mandatory; no advisory suppression or TLS trust
  relaxation is introduced.
- Allow later `2.x` product versions to validate the historical `2.0.0` patch
  seal without rewriting its ten `1.20.x` slots. Keep scope validation and
  rejection of unrelated major lines and malformed versions intact.

all features: 3,291 tests passed, with 43 existing ignored tests. Clippy with
