# gewyvern v1.0.0 Release Notes

`gewyvern v1.0.0` is the project's first sealed stable release.

This release does not claim that the system is finished.
It claims that the core is now coherent enough to be used, judged, operated,
and extended without relying on tribal memory.

## Release Summary

`v1.0.0` marks the point where:

- the runtime, CLI, compiler, protocol shelf, and documentation now present
  one stable core story
- release judgment starts from native validation entrypoints instead of ad hoc
  shell sequences
- Linux-host proof, eBPF attach evidence, and practical target-lab validation
  are part of ordinary release confidence
- `gewyvern`, `gewyc`, `etragon`, and `leserpent` follow one shared mainline
  version without active drift

## What Is Stable In This Release

The stable claim in `v1.0.0` is centered on:

- the Linux-oriented local network debugger/runtime
- `gewylang` package authoring and `gewyc` compilation flow
- machine-readable JSON outputs and HTML reporting surfaces
- native validation entrypoints and release-gate artifact indexing
- repeatable lifecycle behavior around startup, stop, malformed input, logs,
  persistence, and cleanup

## Highlights

- sealed the final pre-`1.0` convergence work from `v0.20.x` into one stable
  release line
- promoted release validation to native `gewyvern_validate` entrypoints
- preserved remote Linux host validation as a first-class proof path
- kept pathological ingest, debugger cross-validation, and target-lab evidence
  as ordinary release inputs
- aligned core docs and history shelves around the active `v1.0.0` line
- introduced branded project assets and integrated the logo into repo and app
  entrypoints

## Validation Posture At Release

The `v1.0.0` release posture is anchored by a green path that includes:

- packaged/container release validation
- debugger cross-validation
- remote Linux host validation
- JSON artifact-index validation
- practical target-lab checks for suspicious HTTP, denied FTP, and denied LDAP
- dependency vulnerability scans for Rust, NuGet, and frontend packages
- focused `leserpent` and `etragon` security tests

## What Comes Next

The next phase is not "invent a new identity."

It is:

- stabilize `v1.0.x`
- keep the Linux debugger core fast and predictable
- continue reducing operator friction
- treat any new widening as deliberate post-`1.0.0` change management
