# Gewyvern v2.0.0 Release Notes

Release date: 2026-08-30

`v2.0.0` is the first community release of the complete protocolized Gewyvern,
Leserpent, and Leselang infrastructure model.

The release keeps Gewyvern focused on Linux-first network debugging while
making collection, orchestration, presentation, and automation independently
replaceable through stable typed contracts.

## Architecture

- Each kernel or container instance can expose one Gewyvern debugging runtime.
- Each `leserpentd` authority manages multiple Gewyvern runtimes and owns one
  authenticated Web/control service.
- One Leserpent client can manage multiple independent `leserpentd` authorities.
- Avalonia, Web, CLI, and Leselang consume the same protocol operations rather
  than implementing separate control semantics.
- Leselang provides synchronous, deterministic GUI/code automation through a
  Rust parser, HIR, VM, UI protocol, effect journal, and re-entry model.
- Credential-driven reverse deployment can install a daemon first and then use
  that authority to provision or retire Gewyvern runtimes.

## Operator Experience

- The Avalonia application opens on a Hub rather than a connection prompt.
- The first screen recommends Local Orchestra, Quick tour, connecting an
  existing daemon, or deploying a new daemon without requiring an account.
- Advanced provisioning and destructive retirement actions remain collapsed
  until explicitly requested.
- Native desktop, Web, and CLI paths expose the same authority/runtime topology,
  operation state, recovery semantics, and canonical Leselang export.
- Thirty official locale identifiers are supported, with eight complete built-in
  desktop locales and downloadable language-pack support for the remaining set.

## Open Core

All capabilities present at the `v2.0.0` seal are MIT-licensed and available in
the free self-hosted product. A Team Silvortex account is optional and does not
gate local Orchestra, remote authorities, deployment, debugging, Leselang, or
the current GUI/CLI/Web control surface.

Future paid work may add hosted services, but it may not remove or reclassify an
existing 2.0 capability.

## Reliability And Security

The `1.20.0` through `1.20.9` closure window retained evidence for:

- lifecycle, restart, cancellation, recovery, and deterministic replay
- authentication, authorization, secret handling, hostile inputs, and fuzzing
- transport, persistence, UI IR, startup, throughput, and artifact-size budgets
- frontend function-chain and GUI/Leselang equivalence
- Linux runtime and eBPF attachment behavior
- reverse deployment, upgrade, rollback, and state preservation
- macOS NativeAOT packaging, local signing integrity, and rollback
- migration, compatibility, documentation, and status-tensor closure

The release gate and machine-readable evidence remain part of normal
maintenance rather than one-time release ceremony.

## Platform Posture

- Gewyvern's eBPF data plane is Linux-only.
- Leserpent's control plane is independent of eBPF and remains portable.
- macOS and Linux are the primary native operator platforms for this release.
- Windows can use the Web console; native Windows and broader mobile work remain
  post-release tracks.
- Etragon remains advisory and intentionally outside the 2.0 release gate until
  its future deep-learning stack is ready.
- Community macOS artifacts are locally/ad-hoc signed unless a release asset is
  explicitly marked notarized. Production Developer ID signing and notarization
  remain a separate post-release assurance track.

## Community Artifacts

- `gewyvern_2.0.0-1_amd64.deb`: Gewyvern for Debian/Ubuntu x86-64.
- `gewyvern-2.0.0-1.x86_64.rpm`: Gewyvern for RPM-based x86-64 systems.
- `leserpent-control-2.0.0-linux-x86_64.tar.gz`: Linux NativeAOT Leserpent Web,
  daemon, compatibility bridge, installer, and official language packs.
- `Leserpent-2.0.0-macos-arm64-adhoc.zip`: macOS arm64 NativeAOT desktop app
  with its bundled daemon. This community build is ad-hoc signed and is not
  Apple-notarized.
- `SHA256SUMS`: SHA-256 digests for all four binary archives.

Verify downloaded files from the same directory with:

```bash
shasum -a 256 -c SHA256SUMS
```

## Compatibility

The v1 wire, schema, migration, and compatibility baselines remain frozen and
tested. Existing self-hosted deployments should follow the normal package or
native installer upgrade path; state and configuration are preserved, and both
Linux and macOS installers retain an explicit rollback route.
