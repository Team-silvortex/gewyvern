# v0.14.x Minor Snapshot

This page records the meaning of the current `v0.14.x` line as a historical
minor snapshot.

Unlike `v0.13.x`, this line is not a convergence shelf anymore.

It is an active `0.14.x` line that should already feel coherent, usable, and
bounded.

## What v0.14.x Means

The `v0.14.x` line means:

- protocol breadth can keep growing without losing shape
- `gewylang` and `gewyc` should feel reusable, not experimental
- runtime/report/API surfaces should be understandable enough for real use
- collaboration with nearby sidecars and control-plane layers should be more
  deliberate, but should not bloat the standalone debugger core

## What Was Already Whole Enough

By the time of `v0.14.x`, the project already had:

- a stable-enough diagnosis spine
- a documented read-only latest-snapshot API
- structured `gewylang` package and compiler surfaces
- Linux packaged validation and runtime validation evidence
- real multi-module collaboration evidence in containerized scenarios

The active posture and evidence pages for this line are:

- [docs/field-validation.md](/Users/Shared/chroot/dev/gewyvern/docs/field-validation.md)
- [docs/field-findings.md](/Users/Shared/chroot/dev/gewyvern/docs/field-findings.md)

## What Was Still Intentionally Incomplete

`v0.14.x` still leaves room for:

- more protocol-family depth
- richer compiler ergonomics
- cleaner explanation/reference material
- more mature collaboration surfaces across sibling projects

But these are line improvements, not excuses for losing discipline.

The stable core still has to stay narrow, reviewable, and bounded.

## How This Differs From v0.13.x

`v0.13.x` asked:

- do we finally know what this project is?

`v0.14.x` asks:

- can this clearer project now keep deepening without dissolving its own
  boundaries?

That makes `v0.14.x` a maturity line, not just a convergence line.
