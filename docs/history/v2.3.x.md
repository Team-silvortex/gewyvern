# v2.3.x Maintenance Line

This line maintains the released Gewyvern, Leserpent, and Leselang system.
The [2.0.0 release baseline](v2.0.0-release-notes.md) and existing open-source
core guarantees remain unchanged. Shared product versions do not renumber
frozen protocols, schemas, or historical validation evidence.

## 2.3.0: Shared Release Alignment And Extraction Readiness

- Synchronize the Rust workspace, .NET product version, local package lockfiles,
  release metadata, status checkpoint, and current documentation on `2.3.0`.
  Native desktop bundles and the bundled Rust daemon inherit this shared
  version rather than carrying an independent desktop release number.
- Continue the host-neutral Leselang runtime foundation and embedding track.
  Physical repository extraction is deferred without a replacement version or
  date; the existing acceptance gates, not the product version, decide when
  the full VM is ready to move.
- Retain explicit gates for two-host source/effect/reply/capture/cancel
  verticals, product DTO separation, host-neutral durable graph recovery, and
  reference wire/auth/GUI/CLI/journal parity. The syntax/runtime-core/HIR
  exporter is still a partial source artifact, not a complete independent VM.
- Rebuild the macOS arm64 NativeAOT desktop through the native packaging
  workflow and update through the versioned installer, preserving application
  data and a previous release for rollback.

See the [embedding readiness contract](../leselang-embedding.md#repository-extraction-readiness),
[status tensor](../project-status-system.md), and
[desktop packaging guide](../../apps/leserpent-avalonia/README.md) for the exact
boundaries. Local ad-hoc signing and local packaging checks do not claim Apple
Developer ID signing, notarization, fresh remote-Linux validation, or a green
current-artifact CI run.
