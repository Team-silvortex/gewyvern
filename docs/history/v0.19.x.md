# v0.19.x Minor Snapshot

This page records the meaning of the active `v0.19.x` line.

`v0.19.x` starts after the broad protocol expansion and physical-host
validation work of `v0.18.x`. The purpose of this line is to make `gewyvern`
feel less like a large catalog and more like one integrated local network
debugger.

## What v0.19.x Means

The line means:

- protocol breadth should now feed debugger behavior instead of only registry
  coverage
- cross-validation and negative validation should become ordinary evidence
- startup, stop, logs, persistence, and cleanup should remain predictable under
  failed and pathological inputs
- Gewylang and IR surfaces should absorb protocol knowledge without turning
  into scattered special cases
- `etragon` and `leserpent` should continue following the root version while
  keeping their boundaries clear

## What Is Whole Enough Now

By the time `v0.19.x` opened, the project already had:

- a large packaged protocol catalog with family hubs, shelves, alias docs, and
  registry validation
- observability-oriented protocol families such as OTLP, Prometheus, Loki, and
  Jaeger alongside transport, database, messaging, discovery, tunnel, and
  management families
- runtime config, state, certificate, history, and lifecycle documentation
- Linux physical-host validation evidence for source-tree and package-style
  execution paths
- a native validation direction that is no longer only shell-script based

## What This Line Adds

The active work is to tighten the debugger loop:

- make protocol-family classification and diagnosis surfaces easier to read
- keep protocol package organization close to a standard-library shape
- use cross-checks to prove a diagnosis is real and not only a matching guess
- preserve negative tests for bad clients, broken endpoints, stale state, and
  degraded sidecars
- reduce duplicated wording and unstable names before the final `0.20.x`
  pre-`1.0` seal

## Evidence To Preserve

For this line, preserve concise validation output from:

- `cargo test --workspace --all-targets`
- `cargo test protocol_profiles -- --nocapture --test-threads=1`
- `cargo test -p gewyvern api_persistence -- --nocapture`
- `cargo test -p gewyvern history_cli -- --nocapture`
- `cargo test -p gewyvern runtime_config -- --nocapture`
- `cargo test -p gewyvern resilience -- --nocapture`
- physical-host debugger runs that include startup, shutdown, logs, cleanup,
  cross-validation, and negative validation

The important claim for this line is not that the debugger is finished. The
claim is that every major subsystem now has to make the same diagnosis story
clearer, more repeatable, and easier to trust.
