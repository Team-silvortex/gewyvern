# v0.17.x Minor Snapshot

This page records the meaning of the now-open `v0.17.x` line as a durable
minor snapshot.

Unlike `v0.15.x`, which operationalized runtime layout and upgrade posture, and
unlike the `v0.16.x` checklist line, `v0.17.x` is where protocol clusters and
compiler/IR maturity are expected to feel more deliberate together.

## What v0.17.x Means

The `v0.17.x` line means:

- protocol growth should prefer deeper family clusters instead of isolated
  one-off entries
- runtime evidence and history posture should remain strong enough that new
  protocol claims stay reviewable
- `gewylang` and IR evolution should become easier to reason about as stable
  structured layers instead of only implementation detail
- control-plane and debugger-facing surfaces should keep converging toward a
  system that feels intentionally integrated, not just feature-rich

## What Was Already Whole Enough

By the time `v0.17.x` opened, the project already had:

- explicit runtime config, layout, and migration contracts
- persisted history/catalog artifacts for minor-line evidence
- stable-enough protocol family shelves and alias indexing
- cross-project collaboration posture that can be archived instead of guessed
- richer failure-semantics coverage across Redis, RADIUS, WireGuard, and other
  protocol families

## What This Line Adds On Top Of v0.16.x

`v0.17.x` adds a stronger “family first” discipline:

- transport-control families can keep splitting into narrower transport-stage
  shelves
- failure, continuation, and validation paths should appear as first-class
  operator surfaces
- protocol additions should land with registry, docs, semantics, and tests as
  one package
- IR/compiler maturity can grow without losing the runtime-evidence spine that
  earlier lines established

One small early example is the QUIC retry surface:

- `quic initial` remains the default transport opening
- `quic retry` now exists as a separate address-validation continuation shelf
- that keeps retry-stage analysis reviewable without collapsing it into either
  generic initial traffic or later crypto/stream progress

Another concrete `v0.17.x` tightening theme is machine-surface discipline for
`gewyc`:

- wrapper routing fields should feel real enough for tools to adopt now
- grouped payload reads should be preferred over older flat siblings
- compatibility fields may stay, but they should stop being the default read
  path for new consumers
- the field-level contract should start naming earliest tightening lines instead
  of pretending every compatibility field is immortal

## Midline Posture

`v0.17.x` is now past the early-open phase.

The line has also picked up:

- project-wide dataflow topology documentation
- debugger-console publication surfaces for local and API read models
- `etragon` federation learning shape for one learning node consuming many
  nearby `gewyvern` target indexes
- a sharper statement that `etragon` learns and enriches while `leserpent`
  coordinates and presents

The second half of the line should close these into a coherent handoff rather
than expanding randomly.

Use the active execution checklist here:

- [docs/history/v0.17.x-midline-checklist.md](/Users/Shared/chroot/dev/gewyvern/docs/history/v0.17.x-midline-checklist.md)

## What Is Still Intentionally Incomplete

`v0.17.x` still leaves room for:

- more transport-control and debugger-oriented protocol clusters
- clearer IR and lowering snapshots for line-to-line comparison
- stronger resilience evidence for multi-instance and degraded-runtime paths
- more explicit machine-surface stability statements before `v1.0.0`

But this line should not become a loose bucket for random feature growth.

## The Practical Question Of This Line

`v0.17.x` asks:

- can protocol depth, runtime evidence, and compiler/IR structure advance
  together without pulling the project apart?

That makes `v0.17.x` a consolidation-and-deepening line, not just another
breadth pass.
