# v2.7.x Maintenance Line

## 2.7.0: Linux Capture And Recoverable History

Gewyvern 2.7.0 is the shared community product release. It builds on the
[2.6 field work](v2.6.x.md) and the MIT open core. The independently maintained
[Leselang foundation](../leselang-repository-handoff.md) retains its own
version and pinned revision.

**Where to use it.** Run the [Linux UDP collector](../live-udp-capture.md) beside
a known workload: select its cgroup and one port, then correlate its observations
with application logs. The collector does not modify or block traffic. The larger
TCP/UDP protocol catalog can analyze supplied facts; its size is not the scope of
the live capture hook.

**What changed.** On an orderly stop the service drains queued observations.
A forced stop can lose an unpublished window: use process liveness, loss
counters and a fresh `run_id` rather than trusting a stale `running` file.
If status, export or API state cannot be written, a previous run's terminal
snapshot is not evidence that this run succeeded. See the
[field fault and repair results](../field-findings.md).

History readers use the committed index. A restart can finish an interrupted
eviction without deleting the entries that index still names, even if the new
writer has a different limit. Raising the limit does not bring evicted runs
back. The [multi-directory recovery test](../production-udp-offload-service.md#changing-retention-between-evictions)
checks both the intermediate index and the final directories on disk.

**Qualification boundary.** These are dated Linux process-crash results, not
power-cut tests, multi-host qualification, or proof of lossless audit capture.
Use separate state/output paths for independent collectors. The [status
catalog](../../project/status/catalog.json) tracks remaining gates. The original
reports retain their build identities and hashes; they are not attestations for
newly built 2.7.0 packages.
